# SymFrog-512 P1024-v3: bug-fix and validation record

This is a minimal, compatibility-preserving implementation audit.
No cipher primitives, security parameters, nonce format, Argon2id settings,
file-format bytes, tag computation, digest computation, or algorithms were
modified. Public v3 KAT and original v2 decryption fixture remain unchanged.

## Verified defects corrected

1. `hash input --out input --force` previously destroyed the input file.
   It now refuses to replace its own input (including same-inode hardlinks).
   **Reproduced before fix; regression passes after fix.**
2. `fsync_dir_of_path()` resolved an absolute root-level destination such
   as `/example.syf` to an empty string rather than `/`, so the final
   directory fsync failed. **Reproduced and corrected.**
3. File encryption/decryption could leak an input file descriptor when
   rejecting identical input/output paths before entering their cleanup
   block. The rejection path now closes the descriptor.
4. The in-memory FrogHash helper in the statistical test suite initialized
   with the **V2** domain label even while invoking **P1024-v3**, producing
   statistics for a different transcript than the public v3 hash. Fixed
   to use V3. Added an in-suite cross-check against `froghash512_file`.
5. The benchmark mislabeled P1024-v3 as v2 and omitted DS_CT on its final
   pad-only block. The benchmark transcript and text now match v3. Actual
   file encryption already handled DS_CT correctly and was not changed.

## Tests executed

- Release compilation with C++23 and project hardening flags: PASS.
- `--test-all`: PASS (18 boundary lengths, raw/passphrase modes, tampering,
  1,154 full-state inverse checks, including the 1,024 state basis bits).
- `tests/test_v3_compatibility.py`: PASS (original v2 fixture and fixed v3
  SHA-256 KAT `cd31ad7c2ee7be356b61dff7c831a157b6c8eaa0d5c8f43f1c5a6aa83c01bc36`).
- `tests/test_io_regressions.py`: PASS.
- Real file encryption/decryption under forced 7-byte `read()` fragmentation
  across 22 message lengths (0 through 65,549 bytes): PASS.
- Full statistical suite: completed, no automated FAIL entries. v3 results
  saved separately under `v3_validation_results/`; original v2 CSVs retained.
- AddressSanitizer + UndefinedBehaviorSanitizer, `--test-all`: PASS.
- P1024-v3 chi: DDT max = 4; maximum absolute LAT = 8; all 16 four-bit
  inputs map distinctly. These do not establish overall security.
- Hash test-suite output equals CLI v3 hash output: PASS.
- `src/symfrog_inspect.py` bytecode compilation: PASS.

## Build environment and limitations

The execution environment provided the real libsodium and OpenSSL runtime
libraries, but not the upstream `libsodium-dev` header package. For local
compilation only, a temporary **unbundled** declaration shim was used against
the real installed libsodium runtime. KDF password-path tests passed, and
the header shim is **not included** in this archive. For authoritative
rebuild and deployment on Ubuntu, install `libsodium-dev` and `libssl-dev`,
then run `make clean && make release && make check`.

A proven permutation inverse, deterministic tests, and sanitizer runs are
not a formal proof of AEAD security. No independent cryptanalytic audit of
P1024-v3 was performed. The source remains experimental and the arXiv v1
paper predates the v3 bijectivity correction. The old v2 statistical data
must not be interpreted as validation of v3.
